## 作品と体験

- Unity製、1人用、総プレイ時間約1時間の短編。借金を抱えた姉が主人公で、妹とともに闇カジノから脱出するため返済を目指す。
- 富裕層の観客が債務者の窮状を楽しむ施設。ディーラーは主人公を精神的・金銭的に追い詰める敵役。
- 勝負を降りる、所持金で続ける、姉自身を段階的に担保にする、妹を段階的に担保・売却する判断が体験の中心。
- 妹の担保・売却には攻略上の直接的なデメリットを付けない予定。一方で妹の状態や姉妹関係に物語上の代償が残る。「ゲーム的には合理的だが、人間的には選びたくない」という葛藤を重視する。
- 姉自身を売り切ると以後の資金源を失い、妹を助ける余地も失いやすくなる。
- イカサマや高度なAIは採用せず、公開情報、Raise、所持金、残り担保から生まれる続行判断を重視する。

## カードゲームの対象範囲

- プレイヤー対NPCディーラーのブラックジャック、ハイカード・デュエル、スリーカード・ポーカー。
- ジョーカーなし52枚。同一ラウンドでカードを重複させない。表裏表示に対応する。
- 金額は整数。所持金など保存対象はセーブされるクラス `PlayerData` に用意する。
- テーブル、カード、チップ、UI素材を可能な限り共用する。
- 担保・売却、ADV会話、シナリオ、演出の本体は別システムとして後から接続する想定。

## 各ゲームの要点

### ブラックジャック

- 初期2枚。プレイヤーは両方公開、ディーラーは1枚公開・1枚非公開。Aは最適な1または11、絵札は10。
- Hit、Stand、初期2枚時のみDouble Down。同額追加後に1枚だけ引いてStand。
- ディーラーは16以下でHit、17以上でStand。Soft 17もStand。
- 初期2枚のAと10点札がBlackjack。通常勝利1:1、Blackjack 3:2、Pushは返却。
- Split、Insurance、Surrenderは使用しない。

### ハイカード・デュエル

- 本作独自ルール。各3枚を配り、プレイヤーの手札は本人に表向きで表示、ディーラーの手札は裏向きで表示する。双方1枚ずつ場へ公開し、1枚目と2枚目の公開後にBETフェーズ、3枚目公開後に合計値で勝負。
- 2～10は数字通り、J=11、Q=12、K=13、A=14。スートは勝敗に使わない。
- Check、Raise、Call、Fold。基本Raise額はInitial Betと同額。各BETフェーズでRe-Raiseはしない。
- ディーラーは公開情報と性格・戦略から判断。Conservative／Aggressiveなど、Raise・Fold頻度を調整可能にする。高度なAIは不要。
- 通常勝利1:1、同点は返却、Foldした側は投入済みの掛け金を失う。

### スリーカード・ポーカー

- Anteを払い各3枚配る。プレイヤーのみ確認可能。FoldでAnteを失うか、Anteと同額のPlay Betを追加する。
- 配布後、ディーラー→プレイヤーの順に、無料で最大1枚・1回だけ交換できる（2026-10-17追加）。交換しない選択も可能。残り山札から引き、捨て札は戻さない。双方の交換判断が終わってからPlay／Foldを選ぶ。
- ディーラーは自分の手札だけで判断し、Flush以上は維持、Pairは残り1枚、High Cardは最小札を交換する。交換中も裏向き。プレイヤーは交換エリアへ1枚ドラッグするか、Keep Handで見送る。
- 役の強さは High Card < Pair < Flush < Straight < Three of a Kind < Straight Flush。
- ストレートはA-K-Qが最高、A-2-3が最低。同役の比較は原文に従う。
- ディーラーはQueen High以上またはPair以上でQualification成立。
- 不成立ならAnteは1:1勝利、Play Bet返却。成立なら比較し、勝ちは両方1:1、負けは両方没収、同点は両方返却。
- Pair Plus、Ante Bonus、その他Side Betは使用しない。

## 将来の実装で守る接続・設計方針

- 資金不足を即敗北・強制Foldにしない。必要額、現在所持金、不足額を外部へ通知し、資金追加後に勝負を再開できるようにする。
- Dealer Raise／Call／Fold／Win／Loseなどのタイミングを外部演出へ提供する。
- カード・山札・シャッフルを共通化し、各ゲームのルール、表示・アニメーション、UI、資金処理、ディーラーAIを適度に分離する。
- 配布やFlipの演出中に次の処理へ進めない。巨大なManager、GameObject.Findの多用、Prefab名の直書きを避ける。
- 小規模作品として読みやすさと修正しやすさを優先し、過剰な抽象化をしない。
- 原文の推奨順序は共通部分 → ブラックジャック → ハイカード・デュエル → スリーカード・ポーカー。各段階で動作確認する。

## 共通カード基盤の追加仕様（2026-10-15）

- ハイカード・デュエルに先行して、汎用山札・UI手札を `Scene_HightAndLow` に実装する。ゲーム固有の配布、得点、BET、勝敗は今回の対象外。
- カードはUIで表示する。Casinoフォルダーのテクスチャを使用し、`Casino/LWRP/Prefabs/PlayingCards` の3Dカードの比率・UV配置を参照する。
- マウスオーバーで選択し、カードの絵柄を少し持ち上げる。ドラッグ中はカードをカーソル位置へ追従させる。
- プレイ範囲は外部から渡されるUIの `RectTransform` とする。ドロップ時のカーソルが範囲内ならプレイとして手札から除外し、カード情報を通知する。範囲未指定・無効・範囲外ならアニメーションで手札へ戻す。
- 今回はプレイ範囲のUIを作成しない。後続作業で空のUIオブジェクトを指定できるようにする。
- 手札・カードUIはプレハブで再利用する。今回専用の起動時配布デバッグ処理は1スクリプトにまとめ、共通プレハブへ含めない。
- 使い方と接続例は `Docs/CardFoundation.md` を参照する。

## ハイカード・デュエルで確定した追加仕様（2026-10-16）

- プレイヤーは表向きの自分の手札を確認して、ドラッグで1枚を選ぶ（2026-10-16変更）。ディーラーの手札は裏向きのまま。ディーラーは場の公開情報だけで判断し、公開するカードは未公開手札から内容を評価せず選ぶ。
- 各BETフェーズはディーラー先手。Dealer Raise → Player Call/Fold。Dealer Check → Player Check/Raise。Player Raiseに対してDealer Call/Fold。Re-Raiseはしない。
- 開始時に双方がInitial Betを投入し、Raiseは同額。勝者が双方の投入額を受け取り、同点は各自へ返却する。Foldでも相手が双方の投入額を受け取る。ディーラーの資金は無制限。
- ディーラーの判断は公開情報だけを渡す別クラスとし、有利・同程度・不利のRaise/Fold確率を調整できるようにする。
- 今回はロジックと演出接続口を実装する。場へ出すカードなどの演出は今後Casinoフォルダーの3Dモデルで行う。配布、選択、公開、BET、各行動、資金不足、結果、精算、終了で処理を挟め、演出完了まで進行を待つ。
- 所持金はPlayerData.casinoMoneyで保持する。初期資金とInitial Betの具体値は起動側が渡す。既存の手札デバッグシーンを自動で本番進行へ切り替えない。
- 実装と接続方法は `Docs/HighCardDuel.md` を参照する。

## ハイカード・デュエルの演出追加（2026-10-16）

- Scene_HightAndLowにCasinoの机・3Dカードを用いた演出を接続する。ディーラーは今回はモデル配置用の空オブジェクトまで作る。
- 選択されたカードを机に置き、公開・比較時はCinemachineCameraで通常視点から俯瞰視点へ切り替える。各視点とカード位置はSceneViewで調整できる。
- ADVを差し込むSOにタイミング、対象者、行動、フェーズ、宴シナリオラベルを設定し、演出管理のInspectorに登録する。選択前・選択後・レイズ前などで会話終了まで進行を待つ。
- 既存の手札デバッグ配布は無効化し、独立した確認用資金で遊べるシーンに接続する。確認用の数値は本編の初期資金・BET仕様を確定するものではない。
- 実際のADVラベル・台詞は今後設定する。設定例SOは無効状態で置く。
- プレイヤーのUI手札は軽い扇状に表示する。共通手札の曲がり具合・傾き・間隔をInspectorで調整可能とし、ドラッグからの復帰時は配置角度も戻す。
- 俯瞰視点ではプレイヤー手札を画面下、ディーラー手札を画面上へスライド退避する。通常視点へ戻す際は元の位置へ戻し、カメラと手札の移動完了後に操作を再開する。
- カメラ背景は下側の暗い赤から上側の赤へのグラデーションとし、上端に暖かい光色を重ねる。背景マテリアルのInspectorから色・光の強さ・広がりを調整する。

## ブラックジャックの追加確定事項（2026-10-16）

- `Scene_Blackjack` はコピー元の机・Cinemachine視点・背景・手札を利用し、Hit / Stand / Double Downで操作する。
- 所持金は整数のまま、掛け金を正の偶数に限定する。通常勝利は元金込み2倍、Blackjackは元金込み2.5倍を返す。
- 初期2枚のBlackjackは配布直後に決着する。双方Blackjackは引き分け、通常の21よりBlackjackを優先する。ディーラーBlackjack時のDouble Down追加支払いは発生しない。
- 資金、3Dカード、カメラ／手札退避、宴待機をCommonへ共通化し、ゲームごとのルールとイベント条件は分離する。設定方法は `Blackjack.md` を参照する。

## 本編進行・イベント条件・BET演出（2026-10-18確定）

- NewGameButtonからOpeningScene、ハイカード、専用ED、ポーカーOP・ゲーム・専用ED、ブラックジャックOP・ゲーム・専用EDを経てEndingSceneへ進む。各ADV終了を待って遷移する。
- 各ゲームのラウンド数はCasinoRoundProgressのInspector設定で、初期値5。勝敗・Foldを問わず精算とRoundEndedイベント完了後に1回を数え、最終ラウンドから専用EDへ自動遷移する。
- 初期所持金1000はPlayerData.SetDefaultDataで設定し、New Gameでリセットする。所持金・フラグはゲーム間で引き継ぐ。各SceneUIの基本BETはInspectorで設定し、初期値10。
- ADVによる基本BET変更は次ラウンドから有効。ポーカーPlay・ブラックジャックDouble Downはラウンド開始時のBETと同額を維持する。
- ハイカードはディーラーRaise直前のADVから今回だけの追加額を指定できる。Callは実投入額の差分、資金不足はその額で待機、精算は実投入額基準。使用後に通常レイズ額へ戻る。ディーラーのRaise選択自体は既存AIに従う。
- PresentationEventにFlag IdとCompletion Flagsを追加。タイミング到達時にtrueの条件付きイベントを全件選び、該当なしの場合だけ未指定イベントを選ぶ。フラグ重複は制限しない。演出前後のStageをまたいで選択を固定し、正常終了後のみ指定フラグを指定bool値へ更新する。
- MyAssets/ScriptableObject/EventのHightCard・Poker・Blackjack各フォルダ直下をエディタで自動登録する。ランタイムでは収録済みカタログを使用する。
- 各Timingに1つずつ56個の既定イベント、OP・EDを含め62個のラベル名表示ADVを用意する。設定方法・宴コマンド・検証方法はDocs/StoryFlow.mdを参照する。
